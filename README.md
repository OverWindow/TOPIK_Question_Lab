# TOPIK Question Lab

TOPIK II 읽기 기출을 문제 유형별로 검토하고 ChatKHU에서 GPT-5.6 Luna, GPT 5.3 Chat, Claude Haiku 4.5, Gemini 3.5 Flash, Gemini 3.1 Flash Lite, K-EXAONE, Solar Pro 3, Llama 4 Maverick, Gemma 3 27B, GPT-5.4 Nano를 비교해 새 문항을 생성하는 로컬 앱입니다. 파인튜닝 대신 승인된 예시와 편집 가능한 유형 분석서를 같은 프롬프트로 전달합니다.

## 설치와 실행

PowerShell에서 다음을 실행합니다.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\setup_topik_lab.ps1
.\run_topik_lab.ps1
```

앱은 기본적으로 `http://localhost:8501`에서 열립니다. Python 3.11 가상환경은 프로젝트의 `.venv`에 만들어집니다.

## ChatKHU 연결

기본 방식은 키가 필요 없는 ChatKHU 웹 수동 모드입니다. 앱에서 완성된 프롬프트를 복사하고 [ChatKHU](https://chat.khu.ac.kr)에서 원하는 모델을 선택해 실행한 뒤 JSON 응답을 앱에 붙여넣습니다.

K-EXAONE을 포함한 기본 모델 ID는 현재 ChatKHU 계정에서 동기화한 허용 목록을 사용합니다. 조직별 허용 목록이 다를 수 있으므로 자동 호출 전 `허용 모델 목록 동기화` 결과를 확인하세요. GPT 5.1, GPT 5.2와 DeepSeek은 활성 비교 모델에서 제외했으며, 과거 실행 기록은 삭제하지 않고 기존 기록으로만 표시합니다.

사이드바의 `모델 선택`을 누르면 ChatKHU 모델 선택 모달이 열립니다. Gateway 키가 있으면 모달에서 조직에 허용된 전체 모델을 동기화하고 검색·복수 선택할 수 있습니다. 키가 없거나 목록에 없는 모델은 모델 ID를 직접 추가할 수 있습니다. 선택은 유형별 DB에 저장되며 분석, 프롬프트 작업실, 문제 생성 화면에 공통으로 적용됩니다.

새 유형 DB의 기본 비교 모델은 GPT-5.6 Luna, Claude Haiku 4.5, Gemini 3.5 Flash 세 개입니다. 유형별로 사용자가 저장한 모델 선택은 기본값 변경과 관계없이 유지됩니다.

사이드바의 `유형 DB 관리`에서는 현재 생성되어 있는 유형 DB를 선택해 삭제할 수 있습니다. 유형 ID 재입력과 확인 체크를 모두 통과해야 삭제 버튼이 활성화됩니다. 원문 텍스트는 유지되며 삭제한 유형을 다시 열면 새 DB가 생성되고 원문 문제가 다시 수집됩니다.

기출 데이터에서 `저장하고 다음 문제`, 검수·비교에서 `평가 저장하고 다음 문제`를 누르면 저장 후 현재 목록의 다음 문제로 자동 이동합니다. 마지막 문제에서는 현재 위치를 유지합니다.

조직에서 Gateway API 키 발급을 허용한 경우 `.env.example`을 참고해 프로젝트 루트의 `.env`에 `CHATKHU_API_KEY` 하나만 입력하면 됩니다. 이 키 하나로 계정에 허용된 여러 모델을 호출하며, 앱의 `허용 모델 목록 동기화`에서 실제 모델 ID를 확인할 수 있습니다. Gateway 호출은 ChatKHU 계정 크레딧을 사용하며 실행 버튼을 직접 누를 때만 발생합니다.

경희대학교 구성원은 학생 월 2,000크레딧, 교직원 월 5,000크레딧을 제공받고 일부 무료 모델은 크레딧이 차감되지 않을 수 있습니다. 사용 가능 모델과 크레딧 정책은 학교 설정에 따라 달라질 수 있습니다.

## 작업 흐름

1. 사이드바에서 문제 유형 DB를 선택합니다. `1~22번`, `25~50번`을 17개 출제 유형으로 나누어 지원하며, 지문이 없는 `23~24번`은 수집·DB 생성·실험 대상에서 제외합니다.
2. `기출 데이터`에서 선택 유형의 번호만 스캔하고 검토합니다. 정답 정보가 없는 문제는 `AI로 누락 정보 보완`에서 한 모델의 제안을 받은 뒤 검토·수정하고 학습 예시로 승인합니다.
3. 3~4번은 추출 원문에 밑줄 정보가 없으므로 문장에서 `[[밑줄 부분]]`처럼 표시하거나 `밑줄 대상 표현`에 직접 입력합니다. 밑줄 지정 전에는 AI 정답 보완과 학습 승인을 진행하지 않습니다.
4. `유형 분석`에서 프롬프트를 ChatKHU에 넣고 모델별 분석을 가져와 비교하거나 공통 분석서를 직접 수정합니다.
5. `프롬프트 작업실`에서 생성 수, 난이도, 모델 ID와 실제 프롬프트를 확인합니다.
6. `문제 생성`에서 ChatKHU 웹 붙여넣기 또는 선택적 Gateway 호출로 결과를 가져옵니다.
7. `검수·비교`에서 문제를 수정하고 점수와 최종 승인 여부를 저장합니다.
8. `내보내기`에서 승인 문제만 TXT, JSON, CSV로 받습니다.

새 HTML 파일은 `html변환`에 넣은 뒤 `기출 데이터 > HTML 변환 후 스캔`을 누르면 됩니다.

유형별 SQLite 파일은 `data/types`에 저장됩니다. 기출, 프롬프트 설정과 버전, 모델 실행 원문, 생성 결과, 사람 평가가 서로 섞이지 않습니다. 기존 `data/topik_lab.db`는 처음 실행할 때 `data/types/grammar_blank.db`로 복사되며 원본은 그대로 보존됩니다.

지원 유형은 문법 빈칸(1~2), 유사 표현(3~4), 짧은 글 소재(5~8), 안내문·도표 내용 일치(9~12), 문장 순서(13~15), 짧은 글 빈칸(16~18), 공통 지문 19~20, 공통 지문 21~22, 신문 제목(25~27), 긴 글 빈칸(28~31), 긴 글 내용 일치(32~34), 글의 주제(35~38), 문장 삽입(39~41), 공통 지문 42~43, 44~45, 46~47, 48~50입니다. 공통 지문 문항은 세트 ID로 묶이며 한 문항에서 지문을 수정하면 같은 실행 또는 기출 세트의 지문도 함께 갱신됩니다.

PDF 텍스트에서 보기 번호나 도표 구조가 사라진 문항은 버리지 않고 `구조 확인 필요`로 가져옵니다. `기출 데이터`에서 지문, 질문, 보기 4개를 직접 복원한 뒤 정답과 해설을 보완하고 승인할 수 있습니다. 문장 삽입 유형은 `주어진 문장`과 `(①)~(④)` 위치를 별도 필드로 관리합니다.

`프롬프트 작업실`의 적용 방식은 두 가지입니다. `공통 프롬프트`는 모델 성능을 같은 조건에서 비교하고, `모델별 최적화`는 문제 유형 공통 규칙 위에 모델별 짧은 실행 지침을 추가합니다. 각 모델 지침은 UI에서 편집할 수 있으며 실제 실행에 사용된 전체 프롬프트는 실행 기록에 보존됩니다.
