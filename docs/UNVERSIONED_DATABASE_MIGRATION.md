# 로컬 PostgreSQL 문항 구조 전환

현재 생성기는 문항 버전 없이 `topik_bank.items`에 현재 내용과 세트 소속을 저장합니다.
기존의 001~005 마이그레이션은 신규 DB 구성과 기존 구조 전환을 위해 유지합니다.
006은 문항 버전을 통합하고, 007은 로컬 미디어 메타데이터를 준비합니다.

## 적용 전 확인

1. 현재 DB 전체를 백업하고 별도 임시 DB에 복원합니다.
2. 복원 DB의 테이블별 행 수·내용, 제약과 뷰를 원본과 대조합니다.
3. `로컬 DB 연결·구조 확인`으로 현재 구조를 읽기 전용으로 확인합니다.
4. 전환이 필요한 경우 복원본에서 먼저 `로컬 발행 연결 확인 및 스키마 준비`를 실행합니다.
5. 문항·세트 ID, 순서, 세트 내용과 보조 이력을 대조한 뒤 원본에 적용합니다.

외부 응시·미디어 테이블이 문항 버전이나 옛 세트 구조를 참조하면 Hub의 이관은 중단됩니다.
외부 참조를 삭제하거나 `CASCADE`로 강제 적용하지 마세요.
한 문항의 다중 세트 소속과 내용이 없는 문항도 이관 전에 해결해야 합니다.
이미 최신 구조인 DB는 다시 전환할 필요가 없습니다.

## 보존과 복구

세트가 참조하던 문항 버전의 내용을 보존하며 미배정 문항은 최신 내용을 사용합니다.
`item_id`, `source_key`, 세트 ID와 순서를 유지하고 문항 버전 이력은 제거합니다.
실패한 마이그레이션의 DDL·데이터 변경은 한 트랜잭션으로 롤백됩니다.
과거 구조로 복구하려면 이관 전 전체 DB 백업과 당시 코드를 사용합니다.

이 생성기는 로컬 PostgreSQL 등록만 지원합니다. 이전 원격 배포 기록은 조회용으로 남기며
원격 DB 복제나 Storage 파일 이동을 수행하지 않습니다.
미디어 점검은 [로컬 미디어 검증 안내](LOCAL_MEDIA_DEPLOYMENT.md)를 참고하세요.
